## 第三批：多用户与剩余审计

已完成：多用户认证（scrypt + cookie/Bearer）、按用户隔离（AsyncLocalStorage）、登录注册页与 NEED_LOGIN 跳转、阅读统计页、WebDAV 浏览页、换源、翻页动画、定时章节检查、AI 摘要（需 key）。

### 明确不做

| 项 | 理由 |
|---|---|
| 书源登录态 / CookieJar | 需要应用内扫码或验证码登录，服务端无法自动完成 |
| 漫画 / 有声 / 视频库 | 另外三种内容形态，超出小说阅读范围 |
| 章节内容落独立文件 | 现已在 SQLite，换存储位置收益极低 |
| AI 资料库 / 关系图谱 | 依赖大模型多次调用与长文上下文，成本高、非核心链路 |

### 剩余小缺口（可做，优先级低）

| 项 | 参考项目 | 说明 |
|---|---|---|
| 书源导出 | hectorqin | 目前只能导入，不能导出为 JSON 备份 |
| 目录内搜索 | reader-next | 长目录（900+ 章）缺章节名过滤 |
| 简繁转换 | reader-next | 用 opencc 做正文繁简切换 |
| 自定义字体 | reader-next | 目前只有字号/行距/背景 |
| 本地备份文件下载 | hectorqin | 备份只推 WebDAV，没有直接下载 JSON |
| 用户管理页 | hectorqin, reader-next | 后端有用户表，界面只有登录/退出，缺账号列表与改密 |
| 书籍详情独立页 | reader-next | 现在是弹窗，深链接分享不便 |
| 段评 / 章节评论 | — | WebView 源里的段评标记在正文清洗时被丢弃 |
| 阅读统计持久化 | reader-next | 统计在进程内，重启清零 |
| 搜索每源进度 | reader-next | SSE 已有，搜索页未按源显示进度 |

以上均不影响核心阅读链路；如需继续，建议按「书源导出 → 目录内搜索 → 用户管理页」顺序做。

## 结论

小说阅读的核心链路（书源 → 搜索 → 详情 → 目录 → 正文 → 进度 → 书架 → 本地书 → 缓存 → 备份）已完整覆盖，并且有 16 个测试套件兜底。

剩余缺口集中在三类：
1. **多用户与登录态**：hectorqin 有完整用户体系，本项目是单用户。
2. **换源与登录书源**：依赖书源登录/验证码的能力，服务端难以可靠模拟。
3. **内容形态扩展**（AI 摘要、漫画、有声、视频）：超出"小说阅读"范围。
